# 接口设计

设计 v0.2，OpenAPI 3.1 完整定义见 api/openapi.json。共 116 个方法与路径组合，包括买家、员工、Java 会员桥接和 Java 员工桥接。接口尚未实现，本次没有发起付费模型调用。

## 调用与鉴权

买家和员工浏览器使用同源 /mall-agent/v1/member 与 /mall-agent/v1/admin。Python 通过 Java 的 /mall-portal/agent-bridge/v1 和 /mall-admin/agent-bridge/v1 验证身份及业务事实。管理浏览器只调用 admin 门面；桥接签名只由服务端生成。模型只调用查询和准备工具，不取得 confirm、员工审批或付款工具。

Authorization: Bearer <当前主体 Sa-Token>。主体 ID 由 Java 返回，禁止相信 x-user-id、前端 member_id 或模型参数。会员与员工登录域分开。每次敏感写请求重新认证；SSE 建连及每30秒复核身份，注销或封禁后断开。员工权限和分配关系逐请求检查；拥有订阅权限不代表可读所有事件。

普通桥接同时需要主体令牌和 X-Agent-Signature；仅核对例外见本文架构收口。服务端签名建议 HMAC-SHA256，签名文本依次为 method、规范path+query（详细算法见架构03分册）、body SHA256、X-Agent-Timestamp、X-Agent-Nonce，以换行连接。时间允许偏差60秒，nonce保留5分钟防重放；服务身份密钥以受限配置注入，不能交给浏览器/模型。重试重新签名并保留原 operation_no。反向代理必须移除外部伪造的内部身份头。

客服代查使用当前员工令牌加短时 access_grant，绑定员工、会话、会员、用途和有效期；Java 独立校验权限和 grant，不能接受任意会员 ID 代查。普通员工、知识运营、客服和系统管理员分别授权；Java 网关新增资源必须默认拒绝未匹配规则。

## 数据格式与通用行为

- JSON UTF-8，snake_case。Java ID 与事件/消息大序号为字符串；自有对象为 UUID。
- 成功格式 code=OK、message、data、request_id；业务失败使用真实 HTTP 状态及稳定字符串错误码。Java 旧接口 HTTP200 内部业务码必须在适配器中检查后转换。
- 日期为带时区 RFC3339；金额非负两位小数字符串，货币 CNY。数量为整数，报价前后所有金额在 Java 精确计算。
- 所有逻辑写操作带 Idempotency-Key UUID；服务端以主体、接口作用域和键去重，同键不同 body 哈希为409。消息还校验 client_message_id。重放前重新鉴权。
- 列表使用 next_cursor / has_more；默认20，上限100。会话按 updated_at,id，历史按 seq，排队按 created_at,id。游标签名绑定主体、筛选及排序，不作为授权凭证。
- 可变对象携带 version，修改请求传 expected_version。不匹配返回409及最新版本，不能默默覆盖。并发领取失败返回实际归属或重新读取提示。
- 二进制附件响应 Cache-Control: private,no-store；不把令牌放 query、日志或外部来源链接中。普通图片10MB，每消息最多5张；知识20MB；录音60秒并建议10MB字节上限。
- 读取删除/不可访问对象统一404，避免泄漏存在性；已授权但事件游标过期返回410。来源曾被授权引用而现已停用时仅返回来源失效。

## 错误及前端处理

| HTTP | 错误码示例 | 行为 |
|---|---|---|
| 401 | AUTH_REQUIRED / AUTH_EXPIRED | 终止流与新操作，引导原登录，恢复后重新读取状态 |
| 403 | PERMISSION_DENIED | 不展示敏感内容；不自动提升角色 |
| 404 | RESOURCE_NOT_FOUND | 不区分不存在和越权对象 |
| 409 | VERSION_CONFLICT / RUN_ALREADY_ACTIVE / IDEMPOTENCY_CONFLICT | 读取最新状态；不重放新业务编号 |
| 409 | ACTION_EXPIRED / ACTION_STALE / QUOTE_CHANGED / STOCK_INSUFFICIENT | 原卡失效，说明原因，重新准备并再次点击确认 |
| 410 | EVENT_CURSOR_EXPIRED / SOURCE_UNAVAILABLE | 分别重新同步快照，或标记来源失效 |
| 413 / 415 / 422 | FILE_TOO_LARGE / MEDIA_UNSUPPORTED / VALIDATION_FAILED | 字段/文件错误就地提示 |
| 429 | RATE_LIMITED / QUOTA_EXCEEDED | Retry-After；保留消息和人工入口 |
| 503 | PROVIDER_UNAVAILABLE / DEPENDENCY_UNAVAILABLE | 查询有限退避；写结果未知转核对，不直接重下单 |
| 500 | INTERNAL_ERROR | 展示 request_id；不返回异常堆栈或秘密 |

## 业务准备与确认

2026-11-14恢复投影补充：Message增加可选的`reply_failure`（code、受控message、可空retry_after）。仅对该消息所绑定且属于同会话的失败/中断run生成，不返回供应商、驱动或任意异常原文；历史、快照及message.completed补传均取当前持久事实。每日额度的retry_after取失败时刻所在UTC日的下一日零点，只表示计量窗口，不承诺供应商恢复。已有更新会员消息后，retryRun拒绝旧问题产生新attempt，前端与服务端同时限制。原Message基础字段、操作标识及迁移版本不变。

四类参数由 ActionParameters 的 oneOf 约束，不能传任意工具名、URL或SQL。CREATE_ORDER 中 DIRECT 使用已选商品/SKU/数量，CART 使用已有 cart_item_ids，两者互斥；DIRECT 报价与创建不修改买家原有购物车。查询地址、优惠券、积分后，Java 返回 Quote，包括逐行金额、优惠分项、地址摘要、规则版本、参数哈希和5分钟有效期。

前端准备操作返回 Action，只有用户点击 /actions/{id}/confirm 并携带版本才把状态推进 EXECUTING。确认请求不接收价格、数量等可变参数。任何编辑都必须产生新的 action_id，旧卡标 STALE。action_id 与 Java operation_no 相同；确认服务签发与真实点击绑定的短时确认凭据，Java 再核对主体、哈希、期限与报价。

Java 最终操作结果 SUCCEEDED/REJECTED 与业务同事务提交。Python 超时标 UNKNOWN；GET 原编号出现 NOT_COMMITTED 仍保持 UNKNOWN，因为原事务可能在途。只有核对清楚才允许重新准备；禁止通过重试回答、刷新或检查点恢复重新创建操作。已成功操作即使卡片随后过期也返回原成功结果。

## SSE 事件

格式为标准 id/event/data 帧，id 为提交有序的全局单调字符串，允许间隙；由事务锁保护的事件时钟分配。data 的完整 JSON Schema 见 sse-events.schema.json；payload 不含内部思考、未筛选参数或他人数据。注释心跳每15秒，不携带业务 ID，也不推进游标。快照与高水位必须一致性读取，重连优先取状态再补传事件。

```text
id: 1208
event: message.delta
data: {"type":"message.delta","event_id":"1208","conversation_id":"5a0f2d23-88cb-4d0f-a431-771fdcb35531","conversation_version":3,"control_epoch":2,"occurred_at":"2026-11-10T12:00:00Z","payload":{"message_id":"fb5e0f15-8319-4151-98d9-e20c953a11e2","run_id":"267d5742-b54a-4353-806d-9055cab9d60f","offset":0,"text":"为你找到以下商品。"}}

```

|---|---|---|
| message.accepted | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| run.started | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| run.queued | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| message.delta | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| message.completed | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| action.updated | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| handoff.updated | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| run.failed | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| run.stopped | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| read.updated | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |
| conversation.updated | 见 Schema 中该事件的 typed payload | 会话所属买家及已授权员工 |

message.delta 的 offset 是目标文本的Unicode码点偏移，前端仅追加符合当前 offset 的数据；重复事件以 event_id 去重，offset不一致则读取最终消息。message.completed 以数据库完整消息覆盖临时增量。停止、人工接管、control_epoch变更使旧 run 后续事件不可展示。

## 权限矩阵

| 角色建议 | 权限范围 | 数据范围 |
|---|---|---|
| 买家 | member接口及四类本人确认 | 仅本人会话、订单、附件与操作 |
| 客服 | conversation:read/reply/note、handoff:claim/close、presence:write、staff:read、business:read、events:subscribe、attachment:upload/read | 当前分配会话；等待列表只显示接待必要摘要 |
| 客服主管 | 客服权限加 handoff:transfer、conversation:history:all、staff:manage | 主管获授权的全量接待历史；受限资料访问留审计 |
| 知识运营 | kb:read/edit；发布者另授 kb:publish；job:read/retry、attachment:upload/read | 对应知识资料与任务；不自动获得私聊或订单访问 |
| 系统管理员 | model、prompt、settings、statistics、audit、retention、backup 各项权限分别授予 | 不因系统配置权限自动获取全部客户私聊 |
| 商城售后/物流员工 | logistics:read/write、return:read/review/receive/refund | Java 再核验业务资源权限；AI 无这些权限 |

上述简写统一前缀 agent:。系统管理员不使用万能角色绕过对象权限。内部备注、秘密配置引用和原始凭证逐用途授权；全量历史查询与当前分配权限明确分离。

## 集成验收前置

接口进入实现后，用 OpenAPI 生成或校验客户端，核验两名买家隔离、员工角色差异、非法状态、幂等哈希冲突、并发领取、报价变化、跨服务超时、事件补传和附件保护。文档及 schema 静态通过不代表接口已运行；供应商 Responses/工具调用/结构化输出/媒体兼容性仍需用独立服务凭据验证。

## 架构收口 v0.2

普通22个Java桥接继续同时要求主体令牌与服务签名。新增 reconcileBridgeOperation 是唯一的后台核对专用例外，必须同时校验 BridgeSignature 和 OperationReceipt；不允许创建业务。QUERY_ONLY 查原结果；FINALIZE_IF_ABSENT 与执行竞争同一操作主键锁，已提交则返回结果，否则原子记录 REJECTED/RECOVERY_NOT_EXECUTED 阻止迟到执行。执行不由恢复 worker 重放；锁超时或依赖失败保持 UNKNOWN。

新增 listModelProfileVersions 返回不可变脱敏配置版本。ModelProfileUpdate 支持 model_name，capability/provider 变更须新建配置。Conversation/Run/Action 及事件增加 control_epoch；version 用于乐观锁，control_epoch 用于生成隔离。上述变化均已同步 OpenAPI 与事件Schema。签名规范、仅核对凭据和跨语言哈希见 architecture/03-关键流程与故障恢复.md。

Snapshot补充recent_messages/history_cursor/handoff/read_position，与event_cursor同一RR快照读取，避免先读游标再读到未来正文。ConversationPage/HandoffPage/JobPage补充同页event_cursor，员工首次订阅从各初始列表高水位的最小值补传，按对象version去重。
