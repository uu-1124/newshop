## 检查边界

上述结果为结构和选定规则校验，不代表完整 OpenAPI 官方符合性、SQL 在目标数据库执行通过或真实业务验收。SQL 需要后续在隔离库验证语法、迁移、并发与恢复；接口需要实现后联调。没有启动数据库、调用模型、变更云端容器或修改商城应用。

可使用 _source/validate_design.py 复查；机器结果见 design-validation.json。

## 原型浏览检查

尝试通过内置浏览器打开本地设计入口时，工具的 URL 策略拒绝 file:// 协议。本次未继续尝试绕过该限制。

因此尚未完成真实浏览器的视觉、窄屏布局、键盘焦点和原生弹窗检查；不能把脚本语法及状态检查视为这些项目已通过。可在本机通过资源管理器直接打开 D:/newshop/docs/index.html 或 ui/index.html 进行评审，页面无需连接商城、模型或数据库。

建议评审顺序：买家选择 B2 规格并准备/确认加车 → 切换历史 → 发起人工接待并到工作台领取 → 保存内部备注后返回买家核对 → 知识构建失败后检查旧版本 → 重新构建发布并查看历史引用 → 留存试算 → 物流与售后分阶段处理。顶部场景选择用于演示异常，重置按钮可恢复示例。
