# 复用 Java 计价与订单创建闭环

日期：2026-11-11。版本：order-0.9。范围：购物车结算、地址与优惠选择、准确报价、买家确认、创建待付款订单与原编号结果核对。

## 复用原业务

原商城本来就有 `generateConfirmOrder`、`generateOrder`、优惠券和积分计算、订单与明细写入、库存预留及超时关闭。本轮从原 `generateOrder` 提取 `previewOrder`，让原商城下单和智能体报价使用同一份 Java 计算。`generateConfirmedOrder` 在原订单事务内核对准备快照，再执行原业务写入；Python 不计算权威价格，不写商城订单表。

智能体先通过真实商品工具给出 SKU 卡；买家加购后，在会话上方点击“选择购物车商品并结算”，明确选购物车行，再读取自己的地址、可用优惠券和积分规则。地址不自动选定，优惠券默认不用，积分默认 0。选好后展示完整确认卡，明确显示商品、数量、脱敏收货地址、活动优惠、优惠券、积分、运费及应付金额。只有买家点击“确认创建订单”才执行下单；结果提供原订单详情入口，由原商城继续承接付款。

当前仅启用 `source=CART`；设计中的 `DIRECT` 直购、取消订单智能体动作与售后动作尚未开放。模型没有确认或执行工具，不能自行选定地址、扣积分、提交下单或付款。原 Java 接口仍可正常结算。

## 计价与变化核对

Java `OrderCheckout` 封装原计算结果。优惠分摊按商城数据库金额精度统一到分，确认卡行金额、订单金额及持久化明细使用同一结果。报价保留 5 分钟，不预留库存、不扣积分、不使用优惠券、不删除购物车、不创建订单。

报价的内部 SHA-256 指纹涵盖商品、规格、数量、各项金额、购物车行编号，以及完整收货地址和电话。公开电话脱敏不能影响变化核对。确认后在 Java 原订单写入前重新计算；任何被确认内容变化都会要求重新准备。库存、优惠券和积分仍由原业务条件更新校验；写入阶段异常回滚，不能把部分失败伪装为一个已提交拒绝。

Java 业务参数规范化使用独立 JSON 编码，保留显式 `coupon_id=null`，避免商城全局 NON_NULL 配置令 Java/Python 参数哈希不一致。执行凭据的类型与用途绑定已扩展到 CREATE_ORDER；订单 audience 与加购 audience 分开。结果和选项投影保留契约要求的 nullable 字段。

## 单次执行与恢复

沿用加购的 PostgreSQL `ag_action`、确认审计、`ag_action_dispatch` 和加密仅核对凭据。首次确认只投递一次 Java execute；重复点击读取同一操作。Java 的订单、订单明细、库存、优惠券、积分和 `oms_agent_operation` 结果同属一个 MySQL 事务。

Java 提交后若响应丢失，PG 保持 UNKNOWN，scheduler 只核对原 operation_no，不能再次下单。核对先封闭未执行操作时，迟到 execute 读取原拒绝。准备阶段增加买家级 PG 事务锁，同一买家任一会话有 EXECUTING/UNKNOWN 时阻止新准备，减少跨会话重试误下单。已在不同会话准备的卡片仍受原购物车互斥、快照与库存校验约束。

成功结果保存的是执行时“待付款”快照。订单此后可能被取消或完成；当前订单状态以原订单详情为准，历史成功操作不能改写成执行失败。

## 增量部署

无需新增容器、PG 表或 PG 迁移。PG 仍为 0006、33 张 ag_ 领域表；复用现有 MySQL 报价、操作和购物车互斥三表。MySQL 报价表新增 nullable `checkout_fingerprint`，旧加购报价允许为空。

部署顺序：运行 `deployment/prepare-order-schema.cjs`，安装包含订单适配器的 portal 包，启用私有配置 `MALL_AGENT_ORDERS_ENABLED` 与 `AGENT_ORDERS_ENABLED`，重启 portal、API、generation、scheduler。可用 `mall-agent/scripts/prepare_orders.py` 准备字段和私有开关。独立 MySQL 测试库增加原订单、地址、优惠等测试表，业务库不复制或重建现有表。

Python 激活接口由 52 增至 53 / 116，新增 `getCheckoutOptions`；Java 新增 `bridgeCheckoutOptions` 并扩展现有 quote/execute/reconcile。`CheckoutSelection` 契约允许先选购物车行再取地址，解决原 ActionParameters 要求已选地址的循环依赖。20 模块和 12 图节点保持原结构。
