# 会员商品选择与自然改选验收

实施日期：2026-11-14，Asia/Shanghai。承接40号新增反例，继续原截图第1组对话准备，并补第2组澄清展示边界；支付、退款、物流保持演示。完整十组目标仍未完成。

**加购与DIRECT准备现增加独立的会员商品/SKU/数量校验；支持明确商品名、型号、规格文字、编号、中文数量及有限多轮修改。未决定、否定或冲突的选择先澄清，不再仅凭模型读过SKU就允许出卡。** 独立工具代理使用当前Java商品事实及可见会员消息再次检查，模型没有确认或执行权限。

本轮同时修正真实验收发现的“请求读取规格误清空选择”“顿号串联地址与不用券/积分导致误拒”及“暂停准备后的澄清仍触发无关商品样本”。保留全部失败，不以最后成功覆盖历史结果。

## 1 选择校验与运行边界

新增[app/agents/item_choices.py](D:/newshop/mall-agent/app/agents/item_choices.py)：

- 只读取会员原始文字；助手、工具、系统文字、图片观察、历史摘要、引文和代码块不能建立选择。
- 对当前可信商品名/含字母数字型号、商品或SKU编号、规格属性及唯一颜色简称作有界匹配。容量G/GB、全角字符和常见中文整数归一；数量必须为1至999的明确整数。
- 必须匹配商品、SKU和数量的完整组合，不能将另一商品的数量借给目标商品，也不能遗漏本次明确选择的其他条目。相同商品的两种规格可分别明确选择。
- “刚才那款改256G、两件”只继承此前会员明确选择的未修改字段；同轮明确改选可覆盖原值。后续未决定、未知规格、否定、冲突、小数/负数/部分ID等不回退到旧肯定选择。
- 多商品后的无目标修改需澄清；超长修改链有数量上限，历史只取有界的会员文字，摘要不替代具体选择依据。
- “读取/核验真实规格”是查询要求，不等于撤销已选规格；“规格保持不变”保留原明确选择。“不要准备”保留暂停意图。

[dialog.py](D:/newshop/mall-agent/app/agents/dialog.py)在prepare前同时检查商品事实、会员商品选择及地址/券/积分。MEMBER_CHOICE_REQUIRED直接返回受控澄清和needs_user_input，不继续消耗模型轮次重试同一个缺参准备。只读查询工具及页面上由本人明确提交的结构化选择保持原路径。

[runtime_tools.py](D:/newshop/mall-agent/app/api/runtime_tools.py)不信任生成进程传来的名称、历史或选择依据。代理按当前身份读取至触发消息为止、仍可见的最近20条会员消息；ADD_CART/DIRECT按去重商品编号读取Java当前商品事实，核对响应商品ID，再执行选择校验。Java读取在SQL锁外，返回后重新检查会话、memory/control epoch、运行租约和fencing；报价/建卡仍由既有Actions.prepare再次围栏。幂等重放读取当前原卡，不再次读取商品或报价。没有新增模型confirm/execute工具、HTTP操作、迁移或交易权限。

当前可信商品集合中的别名唯一性不等于全商城已有语义别名库。自由简称、任意复杂条件、跨多商品省略、超出有界历史的旧选择，以及所有自然语言组合均未宣称覆盖；无法确定时仍要求会员补充。CART、取消和退货沿用各自既有选择/资格/确认路径，本批未把商品校验强套到这些操作。

## 3 暂停准备后的展示修正

实际加购第3轮正确询问规格/数量且没有待确认卡，但购物节点在模型未使用查询工具时又兜底读取全商城样本，带出了无关商品。现于[live_workflow.py](D:/newshop/mall-agent/app/agents/live_workflow.py)增加边界：会员明确暂停准备、模型仅给出澄清且没有工具结果时，保持澄清，不触发无关样本查询。

专项测试必须在该场景禁止search/runtime回调，并验证products为空；不是仅检查页面字符串。最后实际DIRECT_FIXED澄清的回答blocks为空，页面“确认创建订单”及“查看加购确认卡”控件均0。先前已生成的历史样本保留原记录，不追改历史伪装从未发生。最终澄清文本较通用，针对性追问和更广自然表达仍需继续完善。
