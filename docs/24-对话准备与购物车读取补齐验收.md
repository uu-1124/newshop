# 对话准备与购物车读取补齐记录

实施日期：2026-11-13。依据R08/R09/R11/R12、架构N06/N07/N08和T07/T09补齐对话准备，增加T11当前购物车只读工具。支付、退款和物流保持演示。原十组目标仍在推进。

本轮已部署购物车分页桥接、确切准备对象和结算选项绑定、会员结算选择核对及准备成功直接返回确认卡。真实模型六类场景的最新尝试通过，另完成买家加购确认卡浏览器验收。模型仍没有confirm、支付、审批、退款执行工具。

## 已实现能力

| 能力 | 当前实现 |
|---|---|
| 当前购物车 | Java签名与当前登录会员双重校验；按ID稳定分页，每页最多20条；返回当前商品/SKU价格、库存、可用性和下一页，不返回member_id |
| 快照验证 | Python校验ID范围、唯一顺序、分页边界、时区、可用性；从已验证条目计算本页条目数和件数，明确仅为当前页 |
| ADD_CART/DIRECT | 准备前核验本轮实际读取的商品、SKU与可用数量；其他商品查询不能代替 |
| CART | 结算前须读取本轮真实可用购物车条目；不能猜条目ID或改换购买方式 |
| 结算选项绑定 | 准备须匹配同一购买方式、商品/规格/数量或购物车条目的选项；地址、优惠券、积分检查可选范围 |
| 会员结算选择 | 核对仍可见会员消息中的地址/券/积分明确表达；支持ID、完整现有标签、明确默认地址及不使用选项。助手文字、图片、总结、引文或含糊/冲突表达不能替会员决定；服务端准备入口再次复核当前选项和可见消息 |
| 取消 | 必须读取该本人未付款订单ORDER详情；其他订单、列表或已付款状态不能代替 |
| 退货 | ELIGIBILITY先绑定订单详情实际明细；准备再次检查确切订单/明细、资格、剩余数量和原因code |
| 查无结果 | 订单/明细404、409、422返回受限工具结果，允许有界重读或澄清；身份失效和运行围栏仍中断 |
| 卡片完成 | 准备成功直接返回应用说明和待确认卡，省去一次模型追加回答；执行仍须用户点击独立确认接口 |
| 停止接管 | 新购物车读取在IO前后校验身份和run围栏；接管后拒绝旧结果，准备继续使用原有前后校验与幂等 |

设计操作总数更新为127：101个Python设计操作、26个Java桥接；实际Python仍97，20模块/12节点，PG迁移仍0010。已同步API生成源、OpenAPI、覆盖目录和两端生成类型，没有新增数据库迁移。
