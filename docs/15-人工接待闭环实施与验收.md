# 人工接待闭环实施与验收

2026-11-11，当前运行版本 `handoff-0.7`，迁移 `0005`。本机运行 Java、Python 和两端前端；云服务器继续提供 PostgreSQL、Redis、RabbitMQ、MySQL、MinIO、Milvus 等中间件。没有把完整业务系统声明为已完成。

## 已运行的范围

| 环节 | 当前行为 |
|---|---|
| 会员申请 | 显式点击“转人工”，从 AI_ACTIVE 进入 WAITING_HUMAN；默认关闭等待期间 AI，保存申请原因 |
| 等待消息 | 会员可以继续发文字，保存并发出会话事件；默认不创建 AI run |
| 等待期间 AI | 会员可以显式开启或暂停；只影响后续消息，不自动补答积压消息 |
| 取消排队 | 只允许尚未认领的申请；返回 AI_ACTIVE，旧 run 失效，后续新消息可重新触发 AI |
| 队列与认领 | 等待列表按 waiting_since / UUID 升序分页；同一会话仅一个有效接待；并发认领只有一个成功 |
| 员工身份 | 每次请求通过签名 Java bridge 重读启用账号及当前数据库资源权限，不根据 admin 名称隐式授权 |
| 容量 | 先按员工 ID 排序锁定资料，再锁会话及接待；认领和转接都检查 ONLINE、60 秒有效期及当前接待数量 |
| 人工回复 | 仅当前被分配员工、有回复权限且会话处于 HUMAN_ACTIVE 时可发送；client_message_id 和请求幂等键防止重复 |
| 内部备注 | 独立 ag_staff_note 表；不进入 ag_message、会员快照、会员事件和模型历史；备注权限和会话访问范围均在服务端校验 |
| 转接 | 仅当前负责人可以转接；签名 Java bridge 检查目标启用状态及接待权限，Python 检查在线和容量；保存前后员工及原因审计 |
| 结束 | 保存结束原因、关闭接待和会话，后续禁止发送或隐式重开；历史可读，新咨询需新建会话 |
| 在线状态 | 工作台每 20 秒续约，租约 60 秒；失效按 OFFLINE 投影，保留接待归属，不自动交回 AI |

激活了 17 个 reviewed 接口，Python 活跃接口由 31 增至 48，总设计契约仍为 116 个；20 个模块、12 个图节点的结构不变。没有新增容器，本轮复用已有运行基础。

## 接管与旧生成隔离

转人工、取消排队、切换等待 AI、认领、转接、结束都会更新 conversation.control_epoch。涉及旧 AI 时，在会话锁下停止 QUEUED/RUNNING/STOP_REQUESTED run，停止生成中的 assistant 消息，撤销租约并保留真实模型请求所需的槽位冷却期。worker 的追加、心跳、知识引用写入均继续检查 epoch、状态与 fencing token，旧 worker 无法在人工接待后补写。

PENDING_CONFIRMATION action 被标记 STALE；EXECUTING / UNKNOWN action 不在人工切换中擅自改写，后续交易模块需独立核对结果。锁顺序为请求去重、排序员工、会话、接待/run/action、生成槽位、消息、审计、事件时钟；事件时钟仍是最后一个数据库锁。

N09 已接入明确的转人工引导。模型把文字判为 HANDOFF 时提示点击按钮，分类本身不会创建接待、改变控制权或授予权限；实际排队由带会员鉴权、版本号与幂等键的接口完成。这是当前实现的边界。

## 界面与通知

- 买家：显示四种接待状态、员工名称、离线状态、取消排队和等待 AI 选择；关闭后隐藏输入区；SSE 增量按当前 control_epoch、run_id 与消息状态过滤。
- 员工：真实等待队列、我的接待、本人结束的历史、文字回复、独立备注、转交与结束原因、在线状态、接待名称和容量。
- 普通员工无权读取他人的已认领会话；全量历史权限 `agent:conversation:history:all` 未分配给演示接待角色。资料管理权限只分配给当前演示管理员角色；可以进一步拆为主管角色。
- 会话事件沿用 PostgreSQL outbox → RabbitMQ durable confirm → Redis 唤醒 → 会员 SSE，PostgreSQL 仍是事实来源。员工工作台当前每 3 秒读取快照，并非完整 admin SSE 实现；会员人工状态另每 15 秒刷新在线投影。
- 修复后台权限菜单筛选直接修改源路由的问题，避免不同登录或新菜单载入时永久丢失子路由；初次新增角色后需重新登录载入菜单。

入口：员工 `http://127.0.0.1:5100/#/agent/service`，会员 `http://127.0.0.1:5173/#/pages/agent/chat`。复用原有演示账号。新增 `Agent reception staff` 专用角色与菜单，原有角色和资源分配保留；脚本为 `mall-agent/scripts/prepare_reception_staff.py`。

## 尚未完成及下一步

本轮是人工文字接待闭环，仍不等于 R06 / A01 全量完成。人工附件、商品/订单卡片、员工业务上下文、员工 SSE、已读未读统计、主管审计查询、完整历史备注呈现、排班/自动分配、压力与故障演练仍待完成。人工状态暂只接受文字，界面禁用图片，服务端拒绝该状态的图片消息，避免发送无法接待的附件。

下一段优先落实 M06 / M18 的“只读业务上下文 → 生成操作草案 → 会员明确确认 → Java 幂等执行 → 结果独立核对”。先以演示购物车的单一动作验证，服务端重新读取商品与价格，不由 GPT 提交权威金额；随后再扩展订单、取消及售后。正式业务政策与评测集仍须业务确认后导入；当前启用的正式知识文档为 0，不能把设计文档直接当作店铺政策。

保留 `runtime-manifest.json` 与 `knowledge-manifest.json` 作为之前版本的历史证据，以本记录和 handoff manifest 描述当前运行范围。
