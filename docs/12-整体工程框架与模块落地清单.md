# 整体工程框架与模块落地清单

> 本文记录 framework-0.4 的历史状态。本轮列出的员工鉴权、任务消费、MQ/Redis 通知与完整图接线缺口已在 runtime-0.5 实施；运行基础见 [13](13-运行基础实施与验收.md)，最新知识闭环见 [14](14-知识管理与引用闭环验收.md)。其余业务缺口继续保留。

2026-11-11，运行版本 `framework-0.4`。本轮按“先搭建整体框架”的要求补齐全模块结构，接续 [11 图片咨询验收](11-GPT图片咨询闭环验收.md)。总体设计、工程骨架和业务运行分别核对。

## 目前到了哪一步

此前完成的是总体设计和一条可运行咨询链路，尚未覆盖全部模块的代码骨架。本轮补齐了 20 个模块的类型边界、依赖装配和代码位置，116 个设计接口的责任注册，完整 12 节点图的编译骨架，员工端五个工作区，以及 Java 交易/核对/售后的接口边界。

这表示后续模块有确定的接入位置和检查方法。它不表示 116 个接口已经实现，也不表示完整业务运行框架已经验收：当前仍只有 11 个 Python 业务接口激活；通用任务消费、MQ/Redis 通知、员工鉴权和完整图节点还没有生产实现。现有文字/图片咨询沿用已经验证的活动图，完整图骨架尚未替换它。

```text
mall-agent/app/

  application/jobs.py           类型化任务处理器注册与分发；无处理器时拒绝

  workers/jobs.py               后台任务进程的 --check 入口；消费循环待实现
  workers/outbox.py             通知进程的 --check 入口；发布循环待实现

  apis/agent-contracts.ts        从完整 OpenAPI 生成的类型

  agent-contracts.ts            同源生成的买家端类型
```

类型边界是工程内部协议，不替代完整 OpenAPI DTO、鉴权或领域实现。延后模块必须在代码中绑定经过验收的真实实现后才能开放，单改配置不会激活空业务。

## 图、任务与权限的约束

完整图预留 N01 运行检查、N02 上下文、N03 路由、N04 导购、N05 知识、N06 购物准备、N07 订单、N08 售后准备、N09 人工、N10 回复、N11 复核、N12 持久输出。每个节点执行前调用进程内 guard；guard 不进入图状态；共享步骤预算。节点未绑定则 `WORKFLOW_NODE_NOT_ACTIVE`，停止围栏失败直接终止。

图内没有交易确认/执行节点。准备与真实点击确认仍由应用服务区分；Java 恢复核对端口与执行端口分离。图骨架本轮只做注册、编译、条件路由和拒绝测试；意图模型、来源复核等真实节点尚未实现。有界补充查询及完整故障策略仍按设计后续落地。

9 种后台任务已声明类型和处理器注册位置，但本轮未注册业务处理器，未创建任务、消费现有队列或执行清理。`jobs --check` 和 `outbox --check` 是结构检查命令，不是长期运行的消费进程。当前长期运行的 Python 进程仍是 API、generation 和 scheduler 三类。

员工端五个路由接入现有服务器菜单筛选，不新增数据库菜单、角色授权或绕过登录的入口。当前用户未获相应菜单时页面不可见；外壳不请求尚未实现的员工接口，也不显示虚构数量。后续员工身份与权限桥接完成后再联调开放。

`/internal/framework` 是本机结构清单，返回代码位置和接口状态，不返回配置、令牌、密钥、消息或对象内容；不通过商城网关开放。框架构造检查当前依赖整个工作区内的前端/Java 结构文件，后续独立 Python 镜像发布前需将构建清单打包，不能直接只复制 app 目录。

## 复现与下一步

```powershell
Set-Location D:\newshop\mall-agent
$env:PYTHONPATH='.'
$env:PYTHONUTF8='1'
& .\.venv\Scripts\python.exe scripts/check_framework.py
& .\.venv\Scripts\python.exe scripts/generate_web_contracts.py --check
& .\.venv\Scripts\python.exe -m app.workers.jobs --check
& .\.venv\Scripts\python.exe -m app.workers.outbox --check
& .\.venv\Scripts\python.exe -m pytest -q
```

按用户“框架优先”的要求，下一轮先补运行基础：员工鉴权和对象权限、通用任务的 PG 租约/fencing/重试、持久任务与通知适配、完整图的真实 guard/上下文绑定及恢复检查。之后再逐模块填入知识、人工与确认式交易，实现一个就验收一个。当前不继续扩展图片或语音功能，也不把原有商城交易流程当成智能体交易链路已通过。
