## 实现与行为

| 改动 | 结果与目的 |
|---|---|
| chat.vue的failedControls | 停止/转人工/等待AI切换/取消排队请求发出前立即屏蔽当前run；请求失败后记录原会话与control_epoch，再读取权威快照。只有快照通过版本/游标检查且epoch未变化才解除失败命令的屏蔽 |
| 请求失败但实际已提交 | 如果快照control_epoch已经推进，保留屏蔽。HTTP响应丢失不等于命令未执行，不恢复已停止生成的旧delta |
| 权威快照暂不可读 | 保持保守屏蔽，后续成功重同步时统一核对；不会因一次读取失败永久冻结，也不会仅因超时就假定停止成功 |
| 本地屏蔽作用域 | 切换或清空当前会话时清理本地记录；重开历史采用服务端持久内容。旧页面请求返回也按当前会话归属检查 |
| agentStream.ts快照合并 | 只有当前页面已有该消息、该run被屏蔽、服务端文本是在已有文本后追加时，才保留当前显示长度；新加载历史不被钳制为空，服务端更短或替换后的正文可以覆盖旧内容 |
| 等待期间控制 | 暂停等待AI和撤销排队都与服务端围栏一致，立即屏蔽当前run，失败后再核对恢复 |

源码：[chat.vue](../mall-app-web/src/pages/agent/chat.vue)、[agentStream.ts](../mall-app-web/src/services/agentStream.ts)、[agent.ts](../mall-app-web/src/services/agent.ts)。

## 真实页面和SSE验证

夹具脚本为[smoke_stream_ui.py](../mall-agent/scripts/smoke_stream_ui.py)。全部会话均标记TEST ONLY，归属既有专用会员22。使用实际会员API创建会话、在关闭AI的等待模式保存触发消息，然后仅向该新测试对象安装明确标记synthetic_ui_only的受控run。普通生成worker不能领取该run；文本由真实Runs.append/finish、PG事件及网关SSE传输，**没有调用供应商模型，也不把它称为真实模型回答验收**。合成run不占模型生成名额，本次不用于证明容量。

| 专用场景 | 实际验证 |
|---|---|
| stop | 买家页收到第一段含emoji文本；不刷新页面，收到第二段实时正文。点击实际停止按钮后显示已停止并保留部分回复；旧Runs.append返回false，迟到标记未写入正文 |
| 停止历史重开 | 页面切换到其他会话，再返回stop会话，AI消息正文及停止状态保持可见；实际DOM证据单独保存 |
| takeover | 页面在生成时点击转人工，显示等待人工、AI已暂停及已停止。员工通过真实管理API上线、领取和发送专用文字；买家页显示人工身份和回复。随后恢复员工原有效离线状态，页面显示暂时离线但接待保留，AI未自动接回；旧append同样拒绝 |
| reconnect | 页面显示第一段后关闭该测试标签。期间append第二段并finish，再打开页面，通过权威快照显示完整两段正文、没有活动生成。该项是关闭/重开页面，不能称为操作系统断网故障 |
| replay | 真实鉴权网关SSE连接收到一段在线delta，保存event_id后关闭HTTP流。在无连接时追加下一段并完成；使用Last-Event-ID重新连接，恰好补回遗漏delta和message.completed，事件递增无重复，run仍同一个且总数1 |

## 夹具失败及处理边界

1. 前一轮prepare把handoff的201误当200，断言失败发生在排队已提交之后。本轮按实际快照续接同一会话，没有再次创建排队或触发模型。
2. 最初合成run的SQL内联JSON被SQLAlchemy当作绑定参数，事务失败。修正为显式JSON参数；保留resume和diagnostic失败日志。仅输出异常类型和函数/行号，没有输出配置、凭据或原始驱动异常。
3. prepare按消息、排队和run各阶段保存进度，重试读取已有状态。initial_appended标记避免普通重跑重复首段；这是验收辅助脚本，不以它作为生产业务幂等保证。
4. 一次浏览器语义点击停止返回节点定位错误，重新观察页面后通过新AX节点操作并核对真实结果，没有把第一次定位失败记为停止成功。
5. 首次格式命令使用了错误工作目录，随后在正确目录检查并通过；不以先前未检查到文件的命令作为通过证据。
