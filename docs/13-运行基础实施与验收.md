## 员工权限链路

`Gateway → Python StaffAuthorization → Java /mall-admin/agent-bridge/v1/identity → MySQL 当前员工与启用角色资源 → Python 对象权限`。

桥接签名覆盖 GET、完整 mall-admin 路径/查询、空正文 SHA-256、UTC 时间和 UUID nonce，允许 60 秒时钟窗口，Redis 保存 nonce 125 秒拒绝重放。员工与会员使用不同签名密钥，Python 不采信客户端的身份和权限头。查询不使用登录时的权限快照，也没有用户名 admin 的隐式授权。

本轮通过原商城管理接口新增资源 `agent:job:read`、`agent:job:retry`，创建 `Agent runtime operator` 专用角色并追加到演示 admin，保留原角色。禁用角色不再产生 Agent 权限，禁用员工的既有令牌被拒绝。验收用临时员工及角色在 finally 中删除，保留商城原有登录审计。

新增接口（前缀 `/mall-agent/v1/admin`）：

| 方法 | 路径 | 检查 |
|---|---|---|
| GET | `/me` | 当前有效员工身份 |
| GET | `/jobs` | `agent:job:read`、处理器原业务权限、本人或系统任务、签名分页游标 |
| GET | `/jobs/{job_id}` | 同上；其他员工任务隐藏为 404 |
| POST | `/jobs/{job_id}/retry` | read + retry + 原业务权限、归属、版本、幂等键、FAILED 状态及总尝试预算 |

员工端五个工作区仍为页面外壳；本轮交付真实 API 和权限基础，没有把未接线的工作区显示为可用。

## 通用任务与恢复

任务和对应 `ag_job_wakeup` 在同一 PG 事务提交。`FOR UPDATE SKIP LOCKED` 领取可执行类型；每次领取增加 attempts、version 和 fencing_token。续期及结果提交同时验证 owner、fence、RUNNING 和有效 lease。过期任务由持 PG advisory lock 的 scheduler 恢复，旧进程不能再写入结果。

默认租约 30 秒、处理超时 60 秒、最多 3 次自动尝试，退避为 2/4/8…秒，上限 60 秒。自动重试唤醒的计划时间与任务 next_attempt_at 一致。超时取消协程，未知异常只保存安全错误码；不可重试的领域错误直接 FAILED。手工重试要求 expected_version 和 UUID Idempotency-Key，每次增加最多 3 次预算，累计最多 10 次。

通用消费者只运行显式注册的处理器。目前唯一生产处理器 `RUNTIME_CHECK` 检查实际迁移及近期 worker 心跳；不会用空实现将知识解析、备份或清理任务标记成功。新增有副作用的处理器仍须使用 JobLease 做领域级幂等和 fenced 提交，任务框架不提供“恰好执行一次”的保证。

## 通知、断线与重复

Rabbit 使用独立 durable direct exchange `mall-agent.jobs` 和 queue `mall-agent.jobs.v1`，persistent 消息、publisher confirm、mandatory 投递、prefetch=1。消息只含 schema_version、job_id、job_type。非法消息丢弃，合法消息在 PG 结果事务提交后 ACK；重投由 PG 状态和租约防止重复处理。

Redis 频道 `mall-agent:events` 只传 event_id，不传令牌、正文或任务参数。API 监听通知唤醒本地 SSE，实际事件按权限从 PG 读取。断线后重新订阅，丢失的 Pub/Sub 通知由每秒 PG 查询兜底。任务消费者也持续轮询 PG，因此 MQ 通知不承担任务事实存储。

Outbox 外部发布不持业务行锁，收到成功确认后再记 published_at；失败保留 pending 并退避，进程中断可能产生重复通知。Redis/Rabbit 故障不会把尚未发送的通知记成功，也不会删除已提交的任务和事件。

Redis 原来通过命令参数启动。本轮将完整 live ACL（包含未改变的 default 账号）写入原持久卷的 `/data/mall-agent-users.acl`，按实际进程 UID/GID 设置 600，在原 Compose 命令追加 aclfile 并仅重建 Redis 服务，验证新账号仍可用。原 Compose 备份为 `/opt/mall-swarm/compose.yaml.before-agent-runtime`。Rabbit 原商城 vhost/账号保持原权限。

## 完整图与模型

| 节点 | 当前真实接线 |
|---|---|
| N01 | 当前运行租约、停止及会话围栏校验 |
| N02 | 受控历史、归属已校验的私有图片、GPT 图片观察 |
| N03 | GPT 结构化意图分类，独立 workflow-router 提示词版本与调用计量 |
| N04 | 有界只读商品子图，经过内部授权代理访问 Java 商品桥接 |
| N05–N09 | 专项能力未绑定时明确失败，不能靠模型分类激活业务 |
| N10 | 当前对话子图或沿用已得到的导购回复 |
| N11 | 再次校验运行围栏，检查回复非空及长度 |
| N12 | 每段再次检查围栏，写入 PG 消息和 SSE 增量事件 |

当前 N11 是租约与基本输出形状检查，不是尚未开发的知识引用/业务事实审核。图中没有交易确认或执行入口；目前可执行工具仍只有只读 search_products。GPT 负责文字、意图和图片；向量/重排/语音继续保留阿里云适配器，未因本轮接线改变供应商配置。

为确保 N11 通过后再持久输出，本轮先在 worker 缓冲模型回答，再分段写出 SSE；因此首次可见回复会晚于模型首 token。停止或租约失效时拒绝持久输出。模型网络请求可能已经产生费用，仍按现有 unknown usage/配额策略记录。
