## 1 依据与行为变更

依据R08/R09/R11/R12、架构N06/N07/N08及02分册4.2：会员明确选择业务参数，变化后重新准备，参数不可就地修改，确认仍由本人点击。03分册的STALE包含上下文变化，未知执行继续按原编号核对。

| 修正 | 当前行为 |
|---|---|
| 否定选择被错误接受 | “不要演示满减券”“别用演示满减券”“不用100积分”“不要用100积分”不再授权该券/积分；最新否定或不确定表达不能回退采用旧轮肯定选择 |
| 明确修改被一概拒绝 | 支持“地址10改为地址11”“地址从10改成11”“不用券20，改用券21”“积分从100改成200”等；仅明确修改词后的最终选择覆盖前文。无修改关系的相互冲突、问题、条件假设仍要求澄清 |
| 引用及局部编号 | 新增单引号、反引号和『』引用排除；10.5、10abc不匹配地址10，100.5/100abc不匹配积分100；常见英文否定不被误当肯定 |
| 旧卡在下一轮生成前仍可确认 | 成功接收新的会员消息时，同一PG事务将该会话PENDING_CONFIRMATION卡置STALE，error_code=MEMBER_CONTEXT_CHANGED、版本递增，保留原参数/报价，写action.updated后写新消息事件 |
| 消息幂等 | 相同请求或相同client_message_id重放在失效更新前返回原对象，不会撤销后续替代卡；失败接收整体回滚，不提前取消卡 |
| 凭证保护 | 仅释放被本次失效的未提交退货卡保护；已经关联return_apply_id的独立凭证保护保留。附件字节不在发送事务中删除 |
| 已执行/未知结果 | 仅改变PENDING_CONFIRMATION；EXECUTING/UNKNOWN不被新消息取消，继续核对原编号，不再执行一次 |
| 准备请求重放 | 去重缓存只定位原卡；重新读取并验证当前归属、运行围栏和卡状态，返回STALE/EXPIRED等当前事实，不把旧缓存PENDING当作新有效卡 |
| 页面说明 | 有未确认卡时，在发送框旁提示新消息会令旧卡失效；旧卡显示具体失效原因；本地到期标题显示已过期，不再与“待你确认”矛盾，四类重新准备提示分别对应商品/地址/订单/售后 |

新的会员消息一律使当前未确认卡失效，包括澄清、补充及自然语言“确认”。这是保守的上下文边界：用户要执行原卡，应直接点击原卡确认；发送自然语言不执行交易。它不尝试用模型推断“这次消息是否真的改变交易”。发送框已经显示该行为，设计承接同步记录，原Word未修改。

源码：[member_choices.py](../mall-agent/app/agents/member_choices.py)、[conversations.py](../mall-agent/app/application/conversations.py)、[actions.py](../mall-agent/app/application/actions.py)、[chat.vue](../mall-app-web/src/pages/agent/chat.vue)、[CartCards.vue](../mall-app-web/src/pages/agent/CartCards.vue)。没有新增接口或迁移；仍为130设计操作、101实际Python操作、迁移0010。
