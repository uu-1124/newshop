# 事实展示与累计记忆补齐记录

实施日期：2026-11-13。承接原十组目标中的第2组流式、第5组规则问答和第6组复核、记忆、知识工具。本轮补齐核心实现并取得专项、真实模型及浏览器证据；十组总体目标仍未完成。

## 当前实现

| 能力 | 行为与约束 |
|---|---|
| 对象和字段绑定 | 商品、SKU、订单、明细、售后、购物车及结算数据转为带对象、字段、单位的展示事实。模型只选择已有事实编号；最终文字由字段渲染器构造，不接受模型替换金额、数量或对象名称 |
| 政策依据 | 规则正文选自本轮授权、仍活动的资料原文段落，保留条件与否定；读取父段落上下文，避免仅取短切片中的数字。资料内的明显恶意指令、危险链接和敏感模式不会成为展示事实 |
| 无依据处理 | 未检索到资料或模型请求不存在的事实时，不把草稿当政策。一般回复中的经营政策结论进入一次有界检索或明确无法核实；业务准备、确认、权限仍由原服务约束 |
| 真流式 | 完整的事实选择JSON对象一出现即可核验、转换并输出，不等待换行或供应商最终事件。任意自由文字、额外字段、伪造编号、工具调用和半截编号不能进入正文 |
| 来源与中断 | 先绑定引用再写可见政策正文；在同一正文事务内再次锁定并复核来源，撤回后拒绝新delta。已显示正文在停止、失败或租约中断后保留引用，可读且仍受归属、有效版本和留存检查；历史投影标记已失效来源 |
| 知识调用数量 | 纯知识实时路径为路由、检索、事实选择，去掉一次自由文本知识草稿调用；无资料时直接说明未知 |
| N04/N08工具 | 导购、售后节点可调用受控retrieve_knowledge；仍使用当前会员scope，IO前后执行围栏。混合商品/售后事实和政策引用分别复核，不能以政策覆盖实际价格/库存/资格 |
| 累计记忆 | ag_context_summary保存累计扫描进度、来源ID/序号/hash、主题和摘录。逐批向前处理新增历史，早期预算、颜色和其他约束优先保留，不再每次只扫描最近48条旧消息 |
| 更新与删除 | 更新预算等主题时采用后续明确偏好；“继续保留/不变”不覆盖原值。每次使用复核源消息可见性、内容hash、期限和memory_epoch；过期聚合重新从有效源重建，删除、修改或过期内容不得复活 |
| 记忆预算 | 最多32条来源片段、展示约4800字符；每批200消息、单次最多扫描2000消息，有未处理历史时明确标记并在后续继续。只取会员消息，不纳入员工备注、附件字节、密码/验证码/住址等敏感内容；不将摘要当业务事实或确认授权 |
| 提示词治理 | 新fact-selector职责进入不可变提示词版本、run配置快照和实际调用账本；后台可按职责查看/发布。版本切换不改变在途run，模型输出仍受服务器事实协议限制 |

本轮未新增公开HTTP接口或数据库迁移；设计127操作、实际97个Python操作、20模块和12节点，PG仍0010。当前build字符串仍governance-1.0，精确源码和证据见grounding-manifest.json，不以旧build字符串当作本轮内容哈希。

事实展示采用受约束的字段表述和政策原文，相关性与事实选择仍受模型影响。它能阻止已复现的字段数值调换及自由编造政策进入受控展示链，但不构成任意语言、任意恶意资料和全部场景的普遍正确性证明。普通问候、图片线索和会员历史复述仍按各自边界处理。

## 剩余目标

本轮补齐第6组的核心字段展示、累计记忆和N04/N08知识工具，并扩展第2组的真实流式和中断引用。仍需更广多轮、混合政策/业务和端到端故障场景；不能把一个600消息样本扩大为任意历史永不丢信息。

第1组仍有更广用户选择/四类卡片界面矩阵，第2组仍有明显首段/总时延与完整停止接管界面组合，第3/4组物流时间/取消摘要专门浏览器验收尚未收口。第7/8组仍需真实供应商价格账单依据、扩展留存竞态及恢复后删除一致性；未知用量不虚构清零。第9组仍欠完整重启、丢通知和失效权限矩阵及outbox运维告警。第10组跨库一致备份、隔离禁execute恢复、实测RPO/RTO、10买家3客服连续15分钟容量与完整资源告警仍未完成。

原十组目标保持active。支付/退款为演示；语音与反馈仍属于完整项目的独立欠项。
